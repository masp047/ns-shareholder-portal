# 月次レポートの差し替え

当月号のWord原稿を受け取り、前月号を資料室へ移して、`report.html` を入れ替える手順である。

## 始める前に確かめること

次の4点を利用者に確認する。1つでも欠ければ、作業を始めない。

1. 原稿（.docx）の場所と版。どの版が確定版か。
2. チェック（弁護士、各取締役、監査役、CFOほか）が済んでいるか。
3. 何月号か。前月号を資料室へ移してよいか。
4. 公開してよい日時。`main` への反映は即公開になる。

確認した内容を自分の言葉で言い直し、利用者のOKを得てから進める。

## 手順

### 1　ブランチを切る

```
git checkout -b report/YYYY-MM
```

### 2　前月号を資料室へ移す

1. 現在の `report.html` を `archive/YYYY-MM.html` へ複製する（YYYY-MM は前月号の年月）。
2. 複製したファイルの `<title>` を「月次レポート YYYY年M月号」に直す。
3. 前月号の図版を `assets/img/YYYY-MM/` へ複製し、複製したHTML内の画像パスを書き換える。
   当月号の変換で `assets/img/` の同名ファイルが上書きされるためである。
4. `library.html` の「過去の月次レポート」に1行足す。新しい号を上に置く。
   初回は「まだありません」の行を消す。

```html
<li><time datetime="YYYY-MM">YYYY年M月号</time><span><a href="/archive/YYYY-MM">月次株主レポート YYYY年M月号</a></span></li>
```

### 3　当月号を変換する

```
python tools/docx_to_report.py "原稿.docx"
```

表示の読み方は次のとおり。

- 「原文との照合: 一致」→ 原稿の全文字が、同じ順序でHTMLに入っている。
- 「不一致」→ 表示された箇所を調べる。原稿の文言には手を入れない。直すのは変換スクリプトの側である。
- 章の数が原稿と違う → 見出しの書式が想定と違う。スクリプト冒頭の「前提とする原稿の書式」を見る。

### 4　目で確かめる

ローカルで `report.html` を開き、次を見る。

1. 章見出し、節見出し、注記が、原稿と同じ区切りで出ている。
2. 表の行と列が崩れていない。
3. 図版と写真が、原稿と同じ位置に出ている。
4. 数字のカードが出ている。
5. スマホ幅（約400px）で横はみ出しがない。

### 5　ホームのお知らせを足す

`index.html` の「お知らせ一覧」の先頭に1行足す。

```html
<li><time datetime="YYYY-MM-DD">YYYY.MM.DD</time><span><a href="/report">月次株主レポート YYYY年M月号</a>を掲載しました。</span></li>
```

### 6　利用者に見せる

変更点を次の形で報告し、公開の承認を得る。

- 当月号：何月号か、章の数、図版の数、原文照合の結果
- 前月号：資料室のどこへ移したか
- 気づいた点：原稿に残る「[削除]」などの表記、誤字に見える箇所（直さず、列挙する）

### 7　公開する

承認後に `main` へ入れる。Vercelが自動で公開する。

### 8　公開後に確かめる

シークレットウィンドウで次を試す。

1. 未ログインで `/report` → ログイン画面へ戻される。
2. 未ログインで `/archive/YYYY-MM` → ログイン画面へ戻される。
3. ログイン後、当月号と前月号がそれぞれ開ける。

1か2で本文が見えた場合は、ただちに利用者へ知らせる。

## してはならないこと

- 原稿の文言、数字、句読点を変える。
- 写真や図版を縮小、切り抜き、再圧縮する。
- チェック未了の原稿を `main` へ入れる。
- `middleware.js` の公開許可リストに `/archive` や `/assets/img` を足す。
- 利用者のOKなしに先へ進む。

## このスキルの範囲外

- 株主への通知メールの送信。宛先はサイト外の名簿で管理する。
- 原稿の執筆と推敲。別の作業として依頼を受ける。
