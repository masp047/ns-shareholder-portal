## 2　決定事項

1. 立上げを最優先とし、V1.0は必要最低限の機能に絞る。
2. ログインの目的は、不正侵入の防止とログイン履歴の取得である。
3. 利用条件はログイン画面の同意に含める。フッターは将来予測に関する注意事項のみとする。
4. 社長ビデオレターは半期に1度とする。
5. 資料室の規程類は会社定款のみとする。取締役会規程・監査役会規程は載せない。
6. ニュースは月次レポートに入れる。商圏ニュースの独立ページは設けない。
7. 「新しい芽」は、該当がない月は欄ごと出さない。
8. 株主のメールアドレス、公開日時、チェック済みの記録は、このサイトに保管しない。
9. 月次レポートのページは常に当月号を表示する。前月号は資料室へ移す。
10. ソースはGitHub（非公開）に置き、Vercelで公開する。
11. Q&A、問合せ、手続き変更は次期以降の開発項目とする。
12. 表記は「Nasdaq」に統一する。「NASDAQ」とは書かない（2026年10月5日決定）。

## 3　月次レポートの作成プロセス

1. 事前確認（掲載内容を決める）
2. 社長メッセージ、プロジェクトの記載
3. 2の記載に合わせて最新ニュースを探し、記載する
4. 記事を実装する（`report.html` を当月号に書き換える）
5. 推敲
6. チェック（弁護士、各取締役、監査役、CFOほか）
7. 前月号を資料室へ移す
8. 公開（前月号と入れ替え。`main` への反映で自動公開）
9. 株主へ通知メール（件名とリンクのみ。宛先はサイト外の名簿で管理する）

## 5　残課題

優先度の高い順に並べる。

1. **ログイン方式の決定。** 利用者の条件は「IDとパスワードを保有しない」「メールアドレスをサイトに保管しない」「誰が入ったかを知りたい」である。この3つは同時には満たしにくい。株主別の履歴を取るには、株主を見分ける手がかりが1つ要る。候補は、株主ごとの専用URL、株主番号、外部認証サービスによるマジックリンクである。
2. **月次レポートの章立ての決定。** 当初の案は4部（社長メッセージ／プロジェクト紹介／新しい芽／最新ニュース）。9月号は9章構成である。9章を毎月の型にするかは未決。決まれば管理画面の入力項目も確定する。
3. **原稿の仕上げ。** 9月号の本文には「[削除]」の表記と「条件は確定次第ご報告」が残る。原稿側で確定したら差し替える。
4. **「仮」の中身の確定。** 上の表のとおり。
5. **トンマナの基準の整理。** 決着済み（2026年10月5日）。本サイトはコーポレートサイトからリンクされるため、Webはコーポレートサイトに合わせる。社内標準への切替えを一度試したが、同日に戻した。文書類は社内標準に従う。
6. **数字の扱いの基準。** ワイヤーフレームは「予実を載せない」方針。掲載項目設計案 v0.1 は「進捗率と在庫KPIを載せる」案。9月号は実績と目標を区別して載せている。毎月の基準は未決。
7. **社長ビデオレターの公開範囲。** YouTubeの動画はポータルの合言葉では守られない。限定公開でも、URLを知れば見られる。
8. **英語版の要否。** 未決。
9. **本番ドメイン。** ワイヤーフレームは `shareholders.japan-stt.co.jp` を想定。現在はVercelの既定ドメインである。

## 6　つまずいた点と対処

| 事象 | 原因 | 対処 |
| :--- | :--- | :--- |
| ワイヤーフレームを取得しても中身が空だった | 画面をJavaScriptで描画していた | ブラウザで開き、各タブを切り替えて本文を取得した |
| GitHubへ書き込めなかった | 接続アプリの権限が読み取りのみ | 利用者がWeb画面からフォルダをアップロードした |
| 動画を埋め込んだ `index.html` が古いまま上がった | 保存し直した版がフォルダに届いていなかった | 保存後にファイルサイズを照合する手順を足した |
| 書体の読み込み指定が壊れた | `sed` の置換文字列に `&` が含まれていた | 文字列の置換は Python で行う |
| Vercelの案内どおりのメニューが無かった | 画面構成が変わっていた | 設定画面のURLを直接示した |

Claude Code では git で直接反映できるため、2番目と3番目の問題は起きない。
